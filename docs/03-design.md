# 03. 설계

## 1. 기술 결정

| 선택 | 대안 | 근거 | 트레이드오프 |
|---|---|---|---|
| **1) 백엔드** - FastAPI | Django, Express | Python 으로 Gemini SDK 를 바로 쓴다. Pydantic 으로 요청 검증(400 · 422 구분)과 API 문서가 함께 나온다. API 7개 규모에 맞게 가볍다 | Django 의 관리자 화면 · 인증 같은 기본 제공 기능이 없어 확장(JWT 로그인 등) 때 직접 붙여야 한다 |
| **2) 프론트** - Vanilla JS + Tailwind CDN. 프론트는 백엔드가 같은 오리진에서 제공하고, `file://` 로 직접 열지 않는다 | React, Vue | 화면 4종 · 파일 2개(`index.html` · `app.js`) 규모라 빌드 도구가 필요 없다. 같은 오리진이라 CORS 설정이 필요 없다 | 화면이 커지면 상태와 DOM 을 손으로 맞춰야 한다. 컴포넌트 재사용 구조가 없다 |
| **3) DB** - SQLite (SQLAlchemy ORM, 추후 PostgreSQL 전환 고려) | PostgreSQL 즉시 도입 | 파일 하나로 돌아 설치 · 운영이 필요 없다. ORM 을 거치므로 전환할 때 연결 설정 위주로 바꾼다 | 동시 쓰기에 약하다. 팀 공유(확장) 단계에서는 전환이 필요하다. SQLite 전용 설정(`sqlite_autoincrement`)은 전환 때 다시 봐야 한다 |
| **4) CSS** - Tailwind 만. styled-components 금지 | styled-components, 직접 작성한 CSS | CDN 한 줄로 쓰고, 클래스만으로 Mac OS 톤 · 다크 테마 · 360px 반응형을 맞춘다. 스타일 방식을 하나로 고정해 섞이지 않게 한다 | CDN 방식은 빌드 최적화가 없어 운영 배포용으로는 무겁다. HTML 의 class 가 길어진다 |
| **5) 받아쓰기** - Gemini API (`gemini-3.1-flash-lite`). 키는 `.env` 로만 읽고, 저장소에 올리지 않는다 | Whisper 자체 구동, 브라우저 음성 인식 | 받아쓰기와 세 갈래 구분을 같은 API 로 처리한다. GPU · 모델 설치가 필요 없다 | 외부 호출이라 실패 · 지연 · 요금이 생긴다(502 · 재시도로 대응). 녹취가 외부로 나간다 |
| **6) 상태관리** - 모듈 변수 + DOM 직접 갱신 | 상태관리 라이브러리(Redux 등), 프레임워크 상태 | `app.js` 한 파일 안에서 끝나 의존성이 없다. 화면 4종 규모에 충분하다 | 상태가 늘면 갱신 누락이 생기기 쉽다. 변경 감지가 없어 갱신 지점을 직접 관리해야 한다 |
| **7) 디자인 시스템** - Mac OS UI 톤. 화면 요소 이름은 아래 「2. 화면 요소 이름」 표를 따른다. 화면 배치는 `docs/화면구성.pdf` 를 가리키고 옮겨 적지 않는다. 한 번 정하면 바꾸지 않고, 바꿔야 하면 사유를 먼저 적는다 | Material, Ant | 페르소나(개발자 아닌 실무자)에게 익숙하고 차분한 톤. 둥근 모서리 · 부드러운 그림자 · 반투명 카드 · 시스템 폰트로 Tailwind 만으로 만든다 | 정해진 컴포넌트 묶음이 없어 버튼 · 카드 · 모달을 직접 만든다 |
| **8) 테마** - 라이트 / 다크 토글, localStorage, 초기값은 시스템 설정 | 라이트 고정, 시스템 설정만 따름 | 저장한 선택이 있으면 그것을, 없으면 `prefers-color-scheme` 을 따른다. 새로고침해도 유지된다 | 기기마다 따로 저장된다(계정에 묶이지 않음). 다크용 색을 모든 요소에 따로 지정해야 한다 |

## 2. 화면 요소 이름

`docs/화면구성.pdf` 5쪽 id 표를 그대로 옮긴다. **식별자 이름은 변경 금지.** 화면을 다시 만들 때도 같은 이름을 쓴다.

| 요소 | id | 자리 |
|---|---|---|
| 검색 입력 | `q` · `from` · `to` | 목록 화면 상단 |
| 목록 칸 | `cards` | 카드 배치 구역 |
| 넣기 폼 | `title` · `metAt` · `attendees` | 제목 · 일시 · 참석자 |
| 파일 · 본문 | `file` · `body` | 녹취 파일과 받아쓴 본문 |
| 버튼 | `btnUp` · `btnSave` | 받아쓰기 · 정리 |
| 결과 세 칸 | `result` | 요약 · 결정사항 · 할 일 |
| 상세 창 | `modal` | 카드를 누르면 뜨는 겹침 창 |
| 제목 수정칸 | `mTitle` | 상세 창 안에서 제목을 고치는 칸 |
| 할 일 표 | `todoBody` | 표의 본문 행 |

공통 - 상단 고정 헤더에 제목과 탭 3개, 테마 버튼. 본문 최대 폭 `max-w-6xl` 가운데 정렬.

## 4. 의존성 추가 정책

**이 문서(03-design)에 사유를 적기 전에는 도입할 수 없다.** 새 패키지가 필요하면 먼저 아래 표에 쓰임과 사유를 적는다.

### 사전 승인 목록

| 패키지 | 쓰임 |
|---|---|
| `fastapi` | 백엔드 웹 프레임워크. API 7개와 프론트 정적 파일 제공 |
| `uvicorn` | FastAPI 를 띄우는 ASGI 서버 |
| `sqlalchemy` | SQLite ORM. Meeting 모델, 추후 PostgreSQL 전환 대비 |
| `pytest` | 테스트 |
| `httpx` | 테스트에서 FastAPI `TestClient` 가 쓰는 HTTP 클라이언트 |
| `google-genai` | Gemini API 호출 (받아쓰기 · 세 갈래 구분) |
| `python-multipart` | `POST /api/upload` 의 파일 업로드(multipart/form-data) 처리 |
| `python-dotenv` | `.env` 에서 `GEMINI_API_KEY` · `GEMINI_MODEL` 읽기 |
